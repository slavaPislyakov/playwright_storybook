# Skill: Commit Message Generator

Этот скилл предназначен для генерации осмысленных и структурированных сообщений коммитов на основе изменений в коде (git diff).

## Инструкции по генерации

При получении запроса на создание сообщения для коммита, следуй этим правилам:

1.  **Анализ изменений**:
    *   Изучи `git diff` (или список измененных файлов).
    *   Определи основную цель изменений: исправление бага, новый функционал, рефакторинг, обновление документации или тестов.

2.  **Формат Conventional Commits**:
    Используй формат: `<type>(<scope>): <description>`

    *   **Типы (types)**:
        *   `feat`: Добавление нового функционала.
        *   `fix`: Исправление ошибки.
        *   `docs`: Изменения в документации.
        *   `style`: Правки форматирования, отсутствие изменений в логике (semicolons, etc).
        *   `refactor`: Изменение кода, которое не исправляет ошибку и не добавляет функционал.
        *   `test`: Добавление или изменение тестов (Playwright, Storybook tests).
        *   `chore`: Обновление задач сборки, зависимостей, конфигураций (package.json, playwright.config.ts).

    *   **Область (scope)**:
        *   Указывай компонент или модуль, который был изменен (например, `Button`, `Auth`, `Storybook`). Если изменений много, scope можно опустить.

3.  **Описание (description)**:
    *   Пиши на русском языке.
    *   Используй повелительное наклонение или краткое описание действия ("добавить", "исправить", "обновить").
    *   Первая буква — строчная (маленькая), в конце точка не ставится.

4.  **Тело сообщения (optional)**:
    *   Если изменения сложные, добавь пустую строку после заголовка и опиши детали списком.

## Примеры

*   `feat(Button): добавить поддержку темы оформления`
*   `fix(api): исправить обработку ошибки 404 при запросе профиля`
*   `test(storybook): добавить визуальные тесты для компонента Input`
*   `chore: обновить зависимости в package.json`
